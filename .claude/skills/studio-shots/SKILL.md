# Studio 自动配图

给 CodeBlox 课程拍真实 Studio 截图。人不用动手截图，agent 直接驱动 Studio。

## 能做到什么

**十二类都跑通了**（前 8 个单元 162 张全是这么拍的）：

| 类型 | 怎么拍 | 例子 |
|---|---|---|
| 视口（3D 场景） | Lua 搭场景 + 枢轴法对准相机，全自动，居中误差 ±1px | 2.1-s3 / 2.6-s2 |
| 属性面板 | 选中部件 → 滚到目标行 → 按坐标点 → 裁剪 → 画红框 | 2.1-s1 / 2.4-s2 |
| 资源管理器 | 选中**子节点**会自动展开父节点，再裁树 | 2.5-s2 / 3.3-s1 |
| 试玩（小人） | **不进 Play 模式**：编辑模式插一个 Rig 角色，PivotTo 摆位 | 2.4-s3 / 3.7-s3 |
| 代码（脚本编辑器） | 命令栏写 `Script.Source` → 点文档标签 → 裁代码区 | 3.6-s1 / 3.7-s1 |
| 输出面板 | **真按 F5 进 Play 模式**，等脚本 print 出来再裁 | 3.2-s3 / 3.6-s2 |
| 右键菜单 / 弹出列表 | 右键 → 悬停子菜单 → 截图 → 点下去，**必须一次调用内做完** | 3.1-s1 / 3.1-s2 |
| 界面导览（带文字标签） | 全窗口图 + `Annotate` 的 `t='text'` 红底白字标签 | 1.1-s2 |
| 游戏内 UI（计分板 / 菜单） | Play 模式里裁视口的一角；用命令栏（客户端语境）驱动角色和 CoreGui | 6.4-s2 / 6.8-s3 |
| 模态对话框（插入对象…） | 右键 → 悬停子菜单 → 点开 → 剪贴板粘搜索词，**一次调用内做完** | 7.3-s1 |
| 设置 / 保存 / 发布类弹窗 | 菜单或快捷键弹窗 → 剪贴板填字段 → 裁上下两半，**别点主按钮**除非真要落地 | 8.1-s2 / 8.2-s3 |
| 网页 | 浏览器手动开到页面 → `Focus-Win "chrome"` + `Shot` 抓屏 → 裁剪 | 8.3-s4 / 8.5-s3 |

**起始页拍不到** —— 主窗口已经开着 place，菜单里也没有「回到起始页」。做法是**再
`Start-Process` 起一个 Studio 实例**（会停在起始页），按 pid 拿 `MainWindowHandle` 自己
`SetForegroundWindow`（`Focus-Win` 按进程名找，两个实例会认错），切到要拍的那一页 →
截图 → 点右上角 ✕ 关掉那个实例。⚠️ 起始页首屏会列出**用户自己的作品和账号名**，
必须先切到目标页再截，而且只裁到第一张卡片（见「列表类页面的裁剪宽度」那条坑）。

  和踩坑经验，**跟具体单元、具体课文无关，不该随单元增长**。
- **每个单元的场景定义**放仓库里：`scripts/shots/unit-NN.ps1`（视口类）和
  `scripts/shots/unit-NN-ui.ps1`（面板/试玩/弹窗类）。这是**用技能的产物**，不是技能的一部分。
- **课文事实**（菜单路径、Roblox 行为、某一课该怎么讲、哪句话实机跑不通）一律写进
  `AUTHORING.md` 第 5 节，**不要写进这里** —— 抄两份必然不一致。这里只留能抽象成
  「下次拍图该怎么做」的规则。

没法从工具推出来；留着的价值在**重拍** —— 课文改了、Studio 换版本了、构图不满意了，
改两个数字重跑一遍就行，不用从零复盘。文件是 agent 写的，不用人手写。

## 前置条件

1. Roblox Studio 已打开一个 place（有 Baseplate 就行），窗口最大化
2. 屏幕 1920×1080；资源管理器 + 属性 + 输出 三个面板都开着（坐标是按这个布局标的）
3. 底部命令栏可见（「脚本」选项卡 → 命令）
4. 课程里已经写好 `<Shot>` 占位（见 AUTHORING.md），`npm run shots:check` 能列出待拍队列

### Studio 没开的话自己开

```powershell
Start-Process "$env:LOCALAPPDATA\Roblox\Versions\version-*\RobloxStudioBeta.exe"
```

会停在开始页（登录状态还在）。**别去「最近」里开用户的正式作品** —— 点左侧 **模板 →
Baseplate**（第一个）新建一个 Place1。理由不只是安全：资源管理器类的截图很多，全新模板的树
只有 `Camera / Terrain / SpawnLocation / Baseplate`，干净得正好；用户那个 place 里的历史
遗留物会直接入镜。

新建的 place **不要 Ctrl+S**（那是往用户账号里发东西，见「会往用户账号里写东西的图」那条坑）。
代价是 Rig 不会留下来，下次得重跑一次 `New-Rig` —— 它已经是全自动的，成本可以忽略。

开完先自检：`Show-VpProbe`（核对视口矩形）+ `Test-Pipeline`（居中误差应在 ±10px 内）。

### 让人能看到进度

Studio 会被反复置前，人就盯不到 agent 在干什么了。**每次工具调用的最后加一句
`Restore-Console`**，把宿主终端弹回来。它靠往上找第一个有窗口的祖先进程来定位终端，
不认死终端名。反过来注意：下一次调用要截图前必须先 `Focus-Win`，否则截到的是终端
（`ShotWin` / `ShotVP` / `ShotRegion` 自己**不会**置前 Studio）。

## 相机怎么控制的

Studio 编辑模式下写 `CurrentCamera.CFrame` **只有位置生效、旋转被忽略** —— 它永远
让相机看向自己的一个枢轴点 Q（实测三个不同相机位置的视线精确交于一点，模型成立）。
所以每张图的流程是：

1. 在对准点放个透明临时部件并选中 → 点文档标签把键盘焦点给视口 → 按 `F`（聚焦选中物）
   → 枢轴 Q 搬到对准点
2. 把相机摆到 `Q − 视线方向 × 距离`
3. Studio 从这里看向 Q，视线方向正好是 config 里的 `PitchDeg`/`YawDeg`，主体自动居中

换个角度只要改 config 的 `PitchDeg`/`YawDeg`，不用碰视口、不用试探迭代。

## 写视口场景

场景定义放 `scripts/shots/unit-NN.ps1`，格式见 `scripts/shots/unit-02.ps1`。

必填：
- `geo` — 建几何的 Lua，用 `P(名,大小,位置,材质,颜色,透明度)` / `CYL(名,高,直径,位置,...)` /
  `BALL(名,直径,位置,...)` / `PN(...)`。位置是**场景局部坐标**（X 左右、Y 上下、Z 前后，原点在地面）
- `lp` — 对准点（局部坐标），会成为画面正中
- `d` — 相机到对准点的距离。视口 1086×612、FOV 70（垂直），可见高度 ≈ 1.4×d、可见宽度 ≈ 2.5×d，按主体尺寸反推

可选：
- `yaw` — 单独指定这一张的场景斜角（度）。默认 210（=正对 180 + 斜 30）。要读出「两根一样高」
  这种等长关系时用 192 更正对；要看出「穿过一块板子」这种前后关系，反而要转到 240~255 让板子侧过来。
  「一段楼梯一级级升高」也要侧过来（235 左右），正对着拍台阶全叠在一起
- `pitch` — 单独指定这一张的俯角（度），默认 20。要「飞到空中俯视」用 30 左右。
  ⚠️ **别超过 35**：视口垂直 FOV 是 70°，俯角一过 35° 画面顶端就低于地平线，天空全没了，
  Baseplate（2048 见方）铺满整幅 = 一片灰纹理，什么都读不出（55° 完全没法用，踩过）
- `post` — 相机摆好之后再跑的 Lua。**选中高亮必须放这里** —— 相机步骤会清空选择

`P` 建的部件名字自带 `CB_` 前缀；`PN` 用**真名**（面板标题栏、资源管理器里会显示给孩子看），
名字记在 Workspace 的 `CBX` 属性里供清场识别。属性面板类截图一律用 `PN`。

**局部坐标在画面上的方向**（默认 yaw=210 时）：局部 `+X` 在画面**左**边，局部 `−Z` 是**朝镜头**这一侧。
摆小人、摆装饰球要用到，别猜，记这两条。

构图经验：想体现「浮在半空」，把对准点放到物体**上方**（如物体在 y=26，对准点 y=29），
相机就在物体之上俯视，地面和影子会落在画面下半 —— 对准点压到物体下方会变成平视看不到顶面。

## 写面板类截图

样板在 `scripts/shots/unit-02-ui.ps1`，每张一个函数。常用积木（`lib/panel.ps1`）：

```powershell
Select-Named "Part"              # 选中部件，属性面板就显示它
Props-Top                        # 属性面板滚到顶（每张都要！见下面的坑）
Props-Scroll -10                 # 往下滚 10 格
Open-PropDropdown $PROW['Material']   # 展开枚举属性的下拉（要点两下，函数里做了）
Expand-Prop $PROW['Size']        # 展开 Size/Position 成 X/Y/Z 三行
ShotRegion "_x" "props"          # 截图并裁出某块：props/explorer/toolbar/ui/left/vp
ReCrop "_x" "_y" 1458 308 452 312     # 从刚才那张全窗口图里再裁一块，不用重新截屏
Annotate "_y" "v_2_3-s1" @( @{t='box'; x=225; y=264; w=218; h=18} ) 2   # 红框/红圈/箭头/文字标签
```

`Annotate` 的 `t='text'`（红底白字小标签）是给「界面导览」那种图标区域用的：
`@{ t='text'; s='① 资源管理器'; x=10; y=700; size=36 }`。**size 至少 30** —— 全窗口图 1920 宽，
网页上要缩到 ~700px，20pt 的字缩完只剩 7px。

`$PROW` 是属性面板各行的屏幕 y 坐标表（本机实测）。**换机器或换 Studio 版本必须重测**：
`Props-Top` 之后 `ShotRegion "_x" "props"`，Read 那张图自己量。

## 写代码类截图

积木在 `lib/code.ps1`：

```powershell
Set-Code 'workspace.MyPart.Script' @(
  'local part = script.Parent                       -- 找到我住的那个方块'
  'part.Material = Enum.Material.Neon                -- 让它发光'
) -Open
ShotCode "v_3_6-s1" 5 700       # 露出 5 行、宽 700px，行号栏也进画面
```

中文在编辑器里渲染得很好（注释绿、字符串橙、关键字蓝），不用改字体。注释想对齐就
按「**一个汉字算 2 列**」算，统一对到第 51 列。

宽度：网页上 `<Shot>` 是 `w-full`，会把图拉到正文宽度（约 700px）。所以裁窄一点
= 字更大更好认，别为了「完整」裁到 1400px 宽 —— 缩下去孩子就看不清了。
`npm run shots:save` 只缩不放（`withoutEnlargement`），窄图不会被强行放大。

**裁剪宽和红框位置别靠眼估，用这三个公式算**（本机 1920×1080 实测；换机器/换字号要重量一次）：

```powershell
# 行号栏占左边 57px，字宽 8.08px/列（中文算 2 列）
function CodeWidth([int]$Cols) { [math]::Max(360, [int](57 + $Cols * 8.08 + 20)) }
function BoxW([int]$Cols) { [int](57 + $Cols * 8.08 + 10 - 28) }   # 红框右边界，x 固定 28
function CodeRow([int]$N) { [int](($N - 1) * 15.5 + 4) }           # 第 N 行的 y
function CodeRows([int]$N) { [int]($N * 15.5) }                    # 框住 N 行的高
```

- **按感觉估会切字**：早期按 7.2px/列 估，95~103 列的长行全被切在半截上，返工了一轮。
  先数最长那行有几列，再套公式。
- **下限 360**：三四个词的短代码按公式只有 220 宽，CSS 拉到 700 是 3 倍，字就糊了。
  360 起步 = 最多拉 1.9 倍，跟别的代码图（420~520）看起来才是一套的。
- **`CodeRows` 不能再 +4**：多这 4px，红框底边就压到下一行的字上。

## 写输出面板类截图

**必须真按 F5 进 Play 模式**（`Play-ShotOut`）。命令栏 `print` 出来的行尾是
「- 编辑」，还多一行 `> print(...)` 回显；Play 模式里是「你好，Roblox！ - 服务器 -
Script:1」，跟孩子屏幕上一模一样。红字报错更要 Play：能拿到
`Workspace.MyPart.Script:3: attempt to call a nil value` 加下面三行
`Stack Begin / Line 3 / Stack End`，行号信息全在。

`rig.ps1` 说「不进 Play 模式」针对的是**视口**（F5 之后相机归客户端管，枢轴法失效）。
**只裁输出面板不受影响** —— 面板位置在 Play 模式下不动。

⚠️ Play 模式会跑**所有**脚本，多留一个就在输出里多一行。所以每张输出图之前先把别的脚本
删干净（样板里的 `U3-NoScripts`）。⚠️ 脚本也可能躺在 **ServerScriptService** 里，
`GetDescendants` 只扫 workspace 是扫不到的，两边都得清（样板里的 `U5-FreshScript`）。

**「拍一个空的输出面板」也是能用的一张图**（讲「条件不成立 → 什么都没打印」这类）。
裁的时候把上面那条「输出」标题栏和筛选行一起留着（H=100 够），不然一片白孩子认不出是哪个窗口；
这张**别画红框** —— 要表达的就是「什么都没有」，框住一片空白反而像出了错。

**死循环 / 脚本超时是能拍到的，但不是 10 秒**。`while true do print("hi") end` 进 Play 之后
Studio 会硬卡半分钟，实测**约 30 秒**红字才出来，`Play-ShotOut` 的 WaitSec 要给到 35 ——
给 22 会在半路截图，那时重复计数才 `(x555)`，等满了是 `(x4996)`，「一秒里转成千上万次」
这种说法只有后者撑得住。掐断时输出里会补：红字
`Script timeout: exhausted allowed execution time` + `Stack Begin / Line 1 / Stack End`。
**红字那行比计数更值钱** —— 孩子真写出死循环时看到的就是它，裁剪要把它一起圈进来
（从面板顶算 H=90 正好切在它下边界，再高就露出半行 Stack Begin）。
Studio 事后能自己缓过来，但这张**放到最后拍**，等别的图都 `shots:save` 进库之后再跑：
万一崩了要重开，Rig 得重建，前面的图不该跟着一起赔进去。

## 写试玩类截图

不进 Play 模式。F5 之后相机归客户端管，枢轴法失效，还得用 WASD 把小人开到位 —— 不可控。
改成编辑模式插一个角色模型（`lib/rig.ps1`）：

```powershell
New-Rig                          # 虚拟形象 → 角色 → R15 + 网格虚拟形象(2016)，建一次就够
Prep-Rig                         # 关头顶名字标签 + 上色 + 摆迈步姿势
Build-Demo ($geo + (Rig-At 'Vector3.new(0,0,-0.25)')) 'Vector3.new(0,3.4,0)' 242
```

`Rig-At` 的 `y` 给 0 就是**脚踩地面**（模型枢轴正好在脚底）；给「台阶顶面的高度」就是站在台阶上。
`$TurnDeg` 是相对「面朝镜头」再转多少度：0 = 正对镜头，180 = 背对。

**Rig 建好上过色就别再 `Prep-Rig`** —— 摆姿势是往 Motor6D 的 `C0` 上**累乘**，再跑一次腿就掰过头了。
判断依据：`Head.Color` 是 `1, 0.8, 0.4` 就说明上过色、也摆过姿势了。

**拍资源管理器之前 `Stash-Rig`**（搬去 ServerStorage），拍完 `Unstash-Rig`。`Park-Rig` 只把它挪出镜头，
树上照样露着一个 `Rig` 节点 —— 孩子的 Workspace 里没这东西，图就对不上。删了再 `New-Rig` 又慢又容易失败。

默认那个灰扑扑的骨架拍出来很闷，`Prep-Rig` 上完色（黄皮肤 + 蓝上衣 + 深蓝裤子）就是标准
Roblox 小人的样子，画面立刻好看很多 —— 别省这一步。

## 写游戏内 UI 类截图（计分板 / 游戏内菜单 / 试玩全景）

要拍的东西是 **Roblox 客户端自己的 UI**，只在 Play 模式里存在。样板是 `Play-Stand`。三条前提：

**Play 模式下命令栏跑的是客户端语境**（输出行尾标「客户端」）。所以 `Players.LocalPlayer`、
`StarterGui:SetCoreGuiEnabled`、`character:PivotTo` 都能用 —— 这是驱动游戏内 UI 的唯一抓手。

**Touched 类的图要靠 `character:PivotTo` 把小人搬上去，别靠「把部件放到出生点」。**
`SpawnLocation` 是 12×12，Roblox 在这块区域里**随机挑点**放小人，比它小的部件接不住
（实测 6×6 的垫子一次 Touched 都没触发，输出面板全空，排查了一轮；14×14 的地板才稳）。
搬人要用 `task.delay` 排到几秒后 —— 命令栏每跑一条都会往输出面板写回显，得先清掉再让人落地，
否则「只有脚本自己 print 的那一行」和「落地那一大串 Touched」二选一。

**一进游戏左上角就挂一条系统消息**（聊天翻译提示），它**不会自己淡出**（等到 25 秒还在），
而且渲染在游戏内菜单**上面**。用 `SetCoreGuiEnabled(Enum.CoreGuiType.Chat,false)` 关掉；
**别点 unibar 上那个 💬 图标** —— 那是个切换、状态还会被记住，脚本每跑一次反转一次，
重拍时反而把聊天又打开了。

## 出图存进 public/shots

截出来的是 PNG，在 `$env:TEMP\codeblox-shots\`。在**仓库根目录**跑：

```bash
npm run shots:save -- --dry     # 先看要存哪些
npm run shots:save              # 真存
npm run shots:check             # 确认待拍数减少了
```

源目录默认就是技能的输出目录，不用传。只存某几张：`npm run shots:save -- 2.1-s3 2.6-s1`。

自动把 `v_2_1-s3.png` 映射成 `public/shots/2.1-s3.webp`，参数和截图控制台一致（最长边
1600、webp q90），实测 500KB PNG → 20~26KB webp（整幅都是文字的图会大些，40~55KB）。
课程里没有对应 `<Shot>` 的 id 会被跳过，不会产生孤儿图。

用的是 `sharp`（astro 的**间接**依赖）。哪天依赖升级把它弄丢了，退路是截图控制台：
`npm run shots` 开着 → `Set-Clipboard -Path <png>` → 切到控制台标签 → `Ctrl+V` → `Enter`
（会按待拍队列顺序存，所以必须按 `shots:check` 打印的顺序逐张粘）。

看成果：**dev server 用 `localhost:4321`**（不是 127.0.0.1，astro 没绑那个 host）。
截图控制台 `127.0.0.1:4444` 只列**待拍**的，而且不会自动刷新，别拿它当成果页看。

## 已知坑（都踩过，别重复）

### 涉及用户账号 / 隐私的

**会往用户账号或外部服务写东西的图，先问用户再拍**。这类动作有：往云端保存、发布上线、
拍需要登录的网站页面（页面会露出账号名和**其他所有作品**）。开工前把三件事问清楚：
① 能不能建一个**一次性的示范对象**给你拍；② 用户身份（用户名 / 头像）能不能出现在图里；
③ 同一件事有多条路径时走哪条。**别自己替用户决定**，也别顺手点任何「公开 / 分享」类按钮。

**用一次性示范对象拍图时，要主动交代它是空壳**。拍图用的场景往往只有地板 + 出生点 + Rig，
用户自己点进去会发现「啥也没有」，以为发布坏了 —— 事后解释不如事前说明。收尾要不要清理
（归档 / 删除）**等用户开口再做**，那也是动用户的账号。

**必然露出用户身份的图，别自己决定遮盖**。有些字段改不动（如试玩里的玩家名就是登录账号名，
`Player.Name` / `DisplayName` 写都报 `lacking capability WritePlayer`，它会出现在
`print(player.Name)`、资源管理器的 `Players` 树、计分板的「用户」列里）。本项目已定：
**用真名，不做任何遮盖**（用户拍板）。新出现的同类情况仍然先问。

**列表类页面的裁剪宽度要卡在第二张卡片左边**。凡是「我的作品 / 我的体验」这种页面都会把
用户**全部**内容列出来，而图是要发到公网的。实测过的两个例子：一个页面第二张卡片从 x=465
开始（裁 460 宽），另一个从 x=513 开始（从 76 起裁 430 宽）。**每个页面自己量一次。**

### 一次性 / 有副作用的界面

**「处女状态」的弹窗是一次性的，要先拍**。有些窗口只在「还没绑定 / 还没配置」时才弹
（如未绑云端的 place 按 Ctrl+S / Alt+P 会弹窗，绑上之后同样的键直接执行、什么都不弹）。
所以顺序有硬约束：**先把这类弹窗拍完，再去点那个会改变状态的按钮**。补拍要从头新建一个对象。

**别凭老文档想象界面长什么样，先截一张看**。两个不同动作可能弹的是**同一个窗口**，
只有标题和主按钮不同；也可能整个步骤在新版里被删掉了。凡是「课文照老文档写」的地方，
**拍图时按实机重写课文**（这是拍图的一部分，不是额外任务），事实写进 AUTHORING.md 第 5 节。

**长得像的两个弹窗，按钮坐标可能差几十像素**（实测同一个 App 的两个窗口底部按钮是 798 vs 858）。
坐标混用就点空、或者点到别的东西上。**每个弹窗自己量一次并记进单元脚本的常量表。**

**模态对话框会吞掉所有输入**。弹窗开着时，后面几次调用点命令栏、点菜单全部无效（也不报错），
表现是「脚本好像没跑」。发现命令没生效先截一张全屏看看是不是有窗口挡着。

### 弹出层 / 菜单

**右键菜单 / 弹出列表一换工具调用就没了**。每次 PowerShell 调用开头的 `Focus-Win`
（`SetForegroundWindow`）会让弹出层失焦、自动收起。所以「右键 → 悬停子菜单 → 截图 → 点某项」
这一串**必须写在同一个函数里**，中间不能拆成两次工具调用去看中间结果。子菜单用 `Move-To`
悬停 + `Start-Sleep`，比 `Click` 稳。

**「⋯」这类菜单按钮是开关**。已经开着时再点一次是**关掉**它 —— 上一次调用把菜单留在开着的
状态，下一次调用又点了一下，结果截到的是收起后的页面（排查了一轮）。要么在同一次调用里
开完拍完，要么先确认它是关着的。

**资源管理器行尾那个「+」会把右键吃掉**。鼠标悬停在某一行时，行名右边会冒出一个圆形「＋」
快捷插入按钮；右键**正好点在它上面时菜单根本不弹**，而且完全不报错 —— 排查了很久
（连试了「窗口没真激活」「要先点文档标签」几个方向都不对）。所以右键树节点时 x 要**靠左压在
图标/文字上**（`x=58` 稳）。行字很长时 `x=73` 也能成，那是因为「＋」被顶得更右 —— 别依赖。

**右键菜单的项数随「选中几个」变**。多选时没有「重命名」（不能一次给三个东西改名），它
**后面所有项整体上移一行（22px）**。所以偏移表要**按单选/多选分两套记** —— 拿单选量出来的
坐标去点多选菜单，会点到隔壁那项。

### 网页类

**网页截图别用浏览器扩展，用 `Focus-Win "chrome"` + `Shot`**。同一套抓屏管线出来的图跟 Studio
那些图像素风格一致（清晰、不缩放）；扩展截图还得先选浏览器、给站点授权。代价是页面导航要靠
点坐标 —— 每次点之前先 `Shot` 看一眼，**绝对不要盲点网页上的按钮**（网页上一个误点可能就是
改设置、发东西、公开内容）。

**导航走地址栏，别在页面里点着找**。`Click` 地址栏 → `Ctrl+A` → `Set-Clipboard` + `Ctrl+V` →
`Enter`。URL 里要用到的 id 从被拍的 App 里取（Studio 命令栏 `print(game.GameId, game.PlaceId)`）。

**只读的东西可以点，会改状态的控件一律不点**。拍「某个选项被选中」的图时，默认值往往就是
你要的那个，直接框住它就行 —— 为了看清楚而去点一下，就是在改用户的设置。

### 属性面板 / 资源管理器

**属性面板的滚动位置不随选中新部件重置**。上一张滚到底了，下一张按 `$PROW` 的坐标点下去会点到
完全不同的行 —— 而且可能顺手把某个属性**改掉**（第一次就把 Anchored 的勾点没了）。所以每个
面板截图开头都要 `Props-Top`。

**属性面板不是按字母排的，是按分类**。`Anchored` 在「部件」下、`CanCollide` 在「碰撞」下，
中间隔着好几行和一个分类标题 —— 别按「相邻两行」去构图。另外 `CanCollide=false` 时会**多出
一行 CanQuery**，行位整体下移，两张图的裁剪坐标不能混用。

**`Color` 属性行点开没有色板**。它只是变成一个可编辑的 `163, 162, 165` 文本格（要再点值左边的
小色块才弹取色器）。想拍「挑颜色」，用 ribbon 上那块六边形色板，比属性面板直观得多。

**资源管理器里双击改不了名**。当前 Studio 双击树节点没反应（不进改名态），紧接着的 `Ctrl+A`
会**把整棵树全选中**，很危险。改名走 **右键 → 重命名** 或 F2。

**资源管理器的排序不是创建顺序，也不是字母序**。`Camera` / `Terrain` 钉在最前，后面**按类
分组**（SpawnLocation 一组、Part 一组、Model 一组），组内才按字母。行高 20px。
**每次改完树的内容先 `ShotRegion` 看一眼真实行位**，别照抄别处的 y 坐标。

**资源管理器没有「展开节点」的 API**，但 `Selection:Set({子节点})` 会自动把父节点展开。
要展开的 Model 就选它的 children。

### 清场 / 命名

**`CB_CLEAR` 是按名字清场的，会误删 place 自带的东西**。`PN()` 把真名记进 Workspace 的 `CBX`，
下一次 `Build-Demo` 就把**所有**叫这个名字的孩子全删掉 —— 拍过一个假的 `SpawnLocation`，
结果模板自带的那块真重生点一起没了，后面资源管理器的图少一行、试玩的小人掉进虚空。
约定：**place 自带对象的名字（`SpawnLocation` / `Baseplate` / `Terrain`）永远不要登记进 CBX**，
同名的假货拍完自己 `Destroy()`，另外写个 `Ensure-Xxx` 在需要真货的函数开头补回来。

**在界面上改完名字要把新名字补进 `CBX`**。`PN("Part")` 记的是 `Part`，之后在界面上改成「地板」，
`Clear-Scene` 就认不出它了 —— 这个部件会永远留在 place 里。改名后补一句
`ws:SetAttribute("CBX", ... .."地板|")`。

**清场标记别打在部件身上**。早期版本给演示部件加 `CBX` 属性做标记，结果属性面板底部的
「属性」分类把它显示出来，直接入镜。现在名字记在 Workspace 的 `CBX` 属性里。

### 脚本 / 输出

**写 `Script.Source` 有两个前提**。① 别写成 `s.Source="第一行\n第二行"` —— 源码里本来就有双引号
（`print("x")`），会把外层字符串提前闭合，报 `Expected identifier when parsing expression, got
Unicode character U+4f60`。正解是每行用 Lua 长括号 `[[...]]` 包起来再 `table.concat(...,"\n")`。
② 文档**已经在编辑器里打开**时写 `Source` 完全不生效，也不报错，画面上还是旧代码 —— 打开的
`ScriptDocument` 占着缓冲区。要先 `FindScriptDocument(s)` 再 `doc:CloseAsync()`。
这两条 `Set-Code` 都替你处理了。

**同时开着两个脚本文档时，`ShotCode` 会点到上一个脚本**。它点的是**第二个**文档标签
（`DocTabX2`），两个都开着的话第二个标签是先打开的那个。换宿主前先把所有文档关掉：
`for _,d in ipairs(ScriptEditorService:GetScriptDocuments()) do if not d:IsCommandBar() then d:CloseAsync() end end`。

**`LogService:ClearOutput()` 连命令自己的回显一起清掉**。回显是提交时写进去的，比
`ClearOutput()` 早，所以把它放在**同一条命令的最后**就能得到一块全空的输出面板 ——
这正是 Play 模式截图前想要的状态。

**要「干净的输出面板 + 延迟发生的事件」时，`ClearOutput()` 必须并进同一条命令**。走单独一条
命令栏命令实测拍出来面板是空的（而计分板明明记着分，说明脚本跑了）—— 多一次命令栏交互就多
一次不确定。把 `ClearOutput()` 接在驱动动作那条命令的**末尾**，再让动作 `task.delay` 到几秒后
发生，就稳了。

**输出面板会把连续重复的消息合并成一行**。同一句话连着 print 十几遍，面板上不是十几行，而是
**一行**加个 `（x12）`，行首给一个 ▸ 可以展开。拍「被触发了很多次」这类图时别按想象写红框
（第一版画了个框十几行的大框），先跑一遍看实际长什么样。注意计数是变的（同一段代码两次试玩
拍到 x12 和 x10），课文里别把这个数字写死。反过来，两句**交替**出现的话不会被合并。

**输出面板消息一多就停在最底下，直接裁是上下各半行**。`Play-ShotOut` 裁的是固定屏幕矩形，
面板自动滚到底之后行的相位跟只有一条消息时对不上。解法：`Play-ShotOut` 跑完（它已经停了 Play，
消息还留着）再 `Wheel 500 900 20` 把面板滚回顶，然后 `ShotOut` 重截 —— 从第一条消息开始裁，
顺序也才跟课文讲的一致。裁剪高度按行距 17px 去凑，切在行边界上。

### 实机行为别信直觉

**教科书式的说法先实测一遍再用**。典型例子：「站在触发体上分数会疯狂往上涨」在当前 Studio
里不成立（`Touched` 不会因为人站着持续刷；真实现象是**一次踩踏触发好几次**，脚/腿/身子各算
一次，面板合并成一行记 `(x6)`）。**先量真实数字，再回去改课文，别反过来。**

**拍「只触发一次」的成果时，别让小人停在触发体上**。人一直站着，去抖锁一解开、落地余震又触发
一次，面板上就成了 `(x2)`，跟「只记一次」的讲法对着干。靠调等待秒数去卡那个窗口是徒劳的
（人落没落稳本身就带随机性）。改成 `PivotTo` 上去、`task.wait(1.2)`、再 `PivotTo` 回起点，
只可能触发一波，拍几次都一样。

**有些客户端 UI 没有 API 能强制显示**。leaderstats 排行榜就是：`GetCoreGuiEnabled(PlayerList)`
返回 `true` 也照样不显示，显示与否由玩家自己在游戏内菜单里开关。好消息是**开过一次就一直
记着**，后面每次 F5 都自己出现，不用每张图都点一遍。

**Play 模式的相机要自己接管才转得动**。`c:PivotTo(CFrame.lookAt(...))` 只转小人，**相机不跟着
转**，拍出来整条场景歪在画面一边。解法：`cam.CameraType = Enum.CameraType.Scriptable`
（默认的相机脚本就不再每帧覆盖了），然后直接写 `cam.CFrame = CFrame.lookAt(eye, target)`。
编辑模式那套「写 CFrame 只有位置生效」的毛病在 Play 模式**不存在**，想摆哪儿就摆哪儿。

**`New-Rig` 的等待时间别往下调**。切标签页 + 弹对话框 + 网格虚拟形象联网拉资源都要时间，
短了就「RIG 没建出来」。实测 900/1500/2500 失败、1500/2500/5000 成功。另外建 Rig 会在树里多
一个 `Rig` 节点，**资源管理器类的图要在 `New-Rig` 之前拍完**，否则孩子的树里没有它、图就对不上。

### 构图

**一排东西越长，斜角就得越小、距离越远**。5 个方块排一排时 yaw=195（偏 15°）会让这排在深度上
前后差 10 studs，最近那块被透视放大到出画面 —— 收到 188 就好了。「色卡」「等长对比」这类图
本来就该接近正对。

**斜排的一排东西，索引递增的方向要挑对**。斜角构图下画面**左边是离镜头近**的那一头（东西大、
看得清），右边又远又小。所以「先 5 个、再 10 个」这种对比图，第 1..5 个必须落在**左边**：
局部坐标要写 `x = 22.5-(i-1)*5` 递**减**。写成递增的话，「5 个」那张拍到的是右边那截又远又小的
半排，缩到网页上就是一排看不清的小点（第一版就这么拍的，全部重来）。

**成组对比图的机位必须完全一样**（同 lp/d/yaw/pitch、同裁剪矩形）。孩子上下滚页面靠的就是
「只有一处变了」；换了机位这组图就白拍了。

**试玩全景里的一排东西别正对镜头笔直排**。默认试玩机位在小人正后方，一条直线的路整条被小人的
身子挡住，只露出两三个边。斜着排（如每块偏 `(-5,0,-8)`）才能让后面几块从身侧铺出去；小人要站
**离镜头最近**的那一块，站中间的话前面几块全在它背后。

**「可见宽度 ≈ 2.5d」只对对准点所在的那个平面成立**。俯拍一块贴地的大板子时，离镜头近的那个
角比对准点近好几 studs，被透视放大 —— 一块 14×14 的地板按公式算 d=11「够宽」，实测四个角全出画，
一路退到 17.5 才四边都留出余量。俯角越大、主体越贴地，就要退得越多。

### 工具本身

**AMSI 会拦脚本**。截屏 + 模拟鼠标键盘 + 窗口置前写在同一个 .ps1 里，Windows Defender 会判成
RAT 特征直接拒绝加载（报 `This script contains malicious content`）。所以 `cap.ps1`（截屏/画图）
和 `win.ps1`（输入）**必须分开**。另外别在任何文件里写 `GetAsyncKeyState` —— 键盘记录器特征，
一加就被拦。

**别用 SendKeys 打字**。中文输入法会把空格当上屏键吃掉，还会乱改大小写
（`hello from claude` → `hellofromClaude`）。所有文本走剪贴板 + `Ctrl+V`。

**命令栏用「运行」按钮触发，别用 Ctrl+Enter**。后者会偶发不生效；两个都发则命令执行两次。

**旋转写不进去，读回来的值会骗你**。`cam.CFrame = ...` 之后读 `cam.CFrame` 拿到的是你自己写
进去的值（旋转也在），但渲染用的是 Studio 自己的朝向。所以「读值验证通过」不代表画面对了 ——
只能看截图。排查这个绕了很久：两个相差 100° 的俯角渲染出完全一样的画面。

**别试图用公式一步算准构图，也别用「每帧重读朝向再重算位置」**。前者算出来能差 100+ 像素
（因为 Studio 在按枢轴重新对准）；后者会形成正反馈，几秒内相机就跑成纯俯视。正解是枢轴法：
先用 `F` 把枢轴钉到对准点，再摆位置。

**相机保持循环必须互斥**。Studio 会持续把相机拽回去，所以要开个 `task.spawn` 循环每帧写位置。
早期版本用 `os.clock()` 计时退出 —— 循环根本不退，每个场景的循环互相抢相机，拍出来是随机的
哪一个。现在用 `workspace:SetAttribute("CBGEN", n)` 做代数令牌：新循环抬号，旧循环发现号变了
就自己退。

**场景别建在原点**。SpawnLocation 那个太阳贴图会挡镜。库里统一建在 `O = (150,0,0)`，
仍在 Baseplate 上。

**首次跑 Lua 会弹「Dangerous Command Detected」**（因为碰了 CurrentCamera）。点
**Always Continue** 免得每张都拦一次 —— 这会改 Studio 的一个提示偏好。

**`Find-Magenta` 会把亮粉色的部件当成标记球**。判据是 `r>170 且 b>170 且 g<110`，Roblox 的
`Hot pink` 正好落进去，于是 `-Verify` 报了个 `dy=136px` 的假误差。主体是粉/紫系时 `-Verify`
的数字直接忽略，看图。

**`Wheel` 的 dwData 必须是 `int` 不能是 `uint`**。向下滚是 -120，声明成 uint 会溢出报错。

**PowerShell 不分大小写，局部变量别跟参数只差个大小写**。`function Road([int]$Seed)` 里写
`$seed = "math.randomseed(...)"`，赋的是**同一个变量** —— 一个字符串塞进 `[int]` 参数，直接
`InvalidArgument`，而且报错指向函数体、不指向调用处，很难一眼看出。

**`<Shot>` 的 `capture` 里出现 `>` 会让这张图整个消失**。`shots:check` 的总数直接少一张，
不报错、**静默漏掉**。菜单路径在 capture 里一律用 `·` 或 `→`。
